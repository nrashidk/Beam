1. FTA AUDIT FILE (FAF) EXPORT
1.1 FTA Audit File — Overall Structure
The FAF generator (utils/fta_audit_generator.py) exists and produces a ZIP file containing a FAFv1.0.0.csv plus a .sha256 integrity file. However, the current 4-table structure is:

FTA Requirement	Implemented?	Notes
[CompanyData]	⚠️ Partial	Present but missing period start/end dates
[SalesData] (Supply Listing)	⚠️ Partial	Present; see §1.3 below
[PurchaseData] (Purchase Listing)	⚠️ Partial	Present; see §1.2 below
[GeneralLedgerData]	❌ Not found	Entirely absent from FAF generator
Non-editable output	⚠️ Partial	SHA-256 hash provides integrity check, but CSV inside ZIP remains technically editable; no file-level write protection or digital signature applied to the CSV itself

Current columns: TaxAgencyName, FAFVersion, TRN, CompanyName, RegistrationDate, Address, City, Emirate

1.5 General Ledger Table
Status: ❌ Not found / needs to be built

The codebase has a fully functional General Ledger module (JournalEntryDB, JournalEntryLineDB, chart of accounts, double-entry auto-generation for invoices and purchases) but none of this data is exported into the FAF. The FTA-required [GeneralLedgerData] table with debit/credit entries and source document references is entirely missing from fta_audit_generator.py.

Required GL table columns per FTA spec:

TransactionDate, TransactionID, TransactionType, AccountCode, AccountName, DebitAmount, CreditAmount, Description, SourceDocumentType, SourceDocumentReference
2. VAT RETURN FILE GENERATION
2.1 VAT Return Calculation (13-box)
Box	Description	Status
Box 1	Standard-rated sales (excl. VAT)	✅ Calculated from InvoiceTaxBreakdownDB
Box 2	Tax refunds provided	⚠️ Hardcoded to 0.0 — not derived from credit notes
Box 3	Output VAT (5% on Box 1)	✅ Correct
Box 4	Zero-rated sales	✅ Calculated
Box 5	Exempt supplies	✅ Calculated
Box 6	Out-of-scope / reverse charge	✅ Calculated (combined)
Box 7	Total sales	✅ Sum of Boxes 1+4+5+6
Box 8	Standard-rated purchases excl. VAT	✅ Calculated
Box 9	Input VAT on standard-rated purchases	✅ Calculated
Box 10	Purchase expenses	⚠️ Hardcoded to 0.0 — expenses VAT not aggregated into VAT return
Box 11	Input VAT on expenses	⚠️ Hardcoded to 0.0 (flagged in code as "handled separately")
Box 12	Total input VAT	⚠️ Under-reported because Box 10/11 are zero
Box 13	Net VAT payable/refundable	⚠️ Correct formula but inflated if Box 12 is under-counted

Requirement	Status

PRIORITISED DEVELOPMENT BACKLOG
PRIORITY 1 — Critical (Blocks FTA Accreditation)
VAT Return File Export (.xlsx + .xml)

Build GET /vat-return/{id}/download?format=xlsx and ?format=xml
Embed: company TRN, client TRN, company name, software name + version number, period dates into file metadata
Implement correct Box 10/11 (expense VAT) aggregation so Box 12/13 are accurate
Link credit note VAT amounts to Box 2
FAF General Ledger Table

Extend fta_audit_generator.py to include [GeneralLedgerData] section querying JournalEntryDB + JournalEntryLineDB
Columns: TransactionDate, TransactionID, TransactionType, AccountCode, AccountName, DebitAmount (AED), CreditAmount (AED), Description, SourceDocumentType, SourceDocumentReference
FAF CompanyData — Period Dates + Software Version

Add PeriodStart, PeriodEnd, SoftwareName, SoftwareVersion to COMPANY_DATA_HEADERS
Populate from the date range passed to generate_faf_zip()
Forced Password Change on First Login

Add must_change_password: Boolean column to UserDB
Set True when user is created via invite flow
On login, if must_change_password=True, return HTTP 403 with {"require_password_change": true} instead of issuing tokens
Build POST /auth/set-initial-password endpoint that clears the flag
PRIORITY 2 — High (Required for Accreditation Audit)
FAF Currency Enforcement (AED)

At FAF generation time, use total_amount_aed / subtotal_amount × exchange_rate to populate VATAmount and InvoiceValueExclVAT in AED regardless of currency_code
Supply Date in FAF Tables

Add SupplyDate column to both [SalesData] and [PurchaseData] tables using supply_date (already in InvoiceDB)
Weekly and Annual Reports

Extend /reports/periodic to support period_type=weekly and period_type=annual
Add GET /reports/annual?year=YYYY endpoint
Report File Downloads

Add ?format=pdf, ?format=xlsx, ?format=csv query parameter support to all report endpoints
Implement XLSX export using existing openpyxl dependency
Implement PDF export using existing reportlab dependency
Audit Trail Coverage Gaps

Add log_audit_event() calls for: user role changes, company settings updates, journal entry creation, GL account changes, team member removal
PRIORITY 3 — Medium (Strengthens Compliance Posture)
Audit Log Immutability at DB Level

Add RULE or TRIGGER in PostgreSQL to prevent UPDATE/DELETE on audit_logs table
Or use append-only table pattern with row-level security
User Account Deactivation

Add is_active: Boolean (default True) to UserDB
Block login for deactivated users without deleting records
BUSINESS_ADMIN Role — Complete Implementation

Define explicit permission set for BUSINESS_ADMIN vs COMPANY_ADMIN
Ensure all endpoints handle the role consistently (currently some endpoints skip it)
Journal Entry Edit/Delete Locks

Add explicit PUT /journal-entries/{id} endpoint with enforcement that is_posted=True entries cannot be modified
Add DELETE /journal-entries/{id} endpoint that only allows deletion of unposted entries
Concurrency Locking — Extend Beyond Invoices

Apply version-based optimistic locking to CompanyDB, InwardInvoiceDB, VATReturnDB
PRIORITY 4 — Lower (Accreditation Best Practice)
In-Application Backup Mechanism

Add admin endpoint POST /admin/backup/trigger to initiate a database dump to object storage (S3/R2)
Add GET /admin/backup/list and POST /admin/backup/restore endpoints
Document backup schedule and recovery point objective (RPO)
Bulk Archive Export

Add GET /invoices/archive/export?format=xlsx to allow bulk download of archived invoice records for offline long-term storage
FAF Non-Editability Enhancement

Consider generating the FAF CSV as a password-protected XLSX (using openpyxl workbook protection) or PDF/A in addition to the current CSV+SHA256+ZIP approach, to more clearly satisfy the "non-editable" FTA requirement
Ad Hoc Report Builder

Add a parameterised report endpoint accepting arbitrary from_date, to_date, invoice type, tax code, and customer/supplier filter for genuine ad hoc generation
