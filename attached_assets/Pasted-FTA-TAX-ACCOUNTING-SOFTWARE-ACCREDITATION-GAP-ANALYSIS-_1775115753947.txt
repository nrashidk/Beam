QR CODE COMPLIANCE — CRITICAL GAP
❌ Not FTA-Compliant

This is a significant compliance gap not covered in previous reports:

generate_qr_code() in utils/pdf_invoice_generator.py:160–188 encodes a public URL (public_url parameter) into the QR code.
UAE FTA requirements (and ZATCA-inspired guidelines) for simplified tax invoices specify that the QR code must encode a TLV (Tag-Length-Value) encoded byte sequence containing at minimum:
Tag 1: Seller name
Tag 2: VAT Registration Number (TRN)
Tag 3: Invoice timestamp
Tag 4: Invoice total (incl. VAT)
Tag 5: VAT total
No TLV encoding exists anywhere in the codebase. A grep for tlv, TLV, tag.*length.*value returns zero matches.
The QR code is present on PDFs and in InvoiceDeliveryActions.jsx, but its content is a URL rather than the FTA-compliant TLV payload.

SUPPLIER PEPPOL ID DERIVATION — MINOR COMPLIANCE CONCERN
⚠️ Partially Present

At main.py:7240:

supplier_peppol_id = company.trn[:10] if company.trn else None

The UAE PINT-AE PEPPOL specification requires the participant identifier in the format 0230:{15-digit-TRN} (ICD 0230 = UAE TRN). Using the first 10 digits of the TRN as the PEPPOL ID is non-standard and may cause PEPPOL network routing failures in production ASP integrations.
