3. Why the browser might be blocking it (this is the main issue)

Your backend enables CORS with an allowed origins list:

ALLOWED_ORIGINS = os.getenv(
  "ALLOWED_ORIGINS",
  "http://localhost:5000,http://localhost:3000,http://127.0.0.1:5000,http://127.0.0.1:3000"
).split(",")


GitHub

That means the API will only accept cross-origin requests from those URLs (3000/5000).

But your frontend is a Vite app. By default vite dev runs at http://localhost:5173, not 3000. Your package.json is using plain Vite ("dev": "vite") and there's nothing in what we saw that overrides the port. 
GitHub

So here's what happens in the browser:

You click Save.

Browser sends a CORS preflight OPTIONS request from http://localhost:5173 to http://localhost:8000/company/profile.

The API doesn't include http://localhost:5173 in Access-Control-Allow-Origin, because it's not in ALLOWED_ORIGINS.

Browser blocks the request for security reasons.

Axios sees "Network Error" with no error.response.

Your React code falls back to 'Failed to update company profile'.

That exactly matches what you're describing.

In other words:
Your PUT is being killed by CORS, not by FastAPI logic.

4. How to confirm this in your environment

You can double-check in the browser devtools:

Open DevTools → Console.
If you see something like:

CORS policy: No 'Access-Control-Allow-Origin' header is present...
then it's 100% this.

Open DevTools → Network tab → click the failed PUT /company/profile request.
If Status is (canceled) or never shows any response headers from your API, that also means it never made it past CORS.

If instead you see a real HTTP status like 401 or 403 and a JSON body with "detail": "Only company admins can update company profile", then it's a permissions/token issue (see section 5 below). But based on the fallback message you're getting, CORS is more likely.

5. All possible reasons this could fail (ranked most → least likely)
A. CORS origin mismatch ✅ (most likely)

Frontend is running on http://localhost:5173 (Vite default).

Backend only allows http://localhost:3000, http://localhost:5000, etc. 
GitHub

Browser blocks the request, UI shows generic "Failed to update company profile".

Fix:
Update your backend CORS ALLOWED_ORIGINS to include your real frontend origin.

For local dev:

export ALLOWED_ORIGINS="http://localhost:5173,http://127.0.0.1:5173,http://localhost:3000,http://127.0.0.1:3000"


(or the equivalent in your .env / deployment config)

Then restart the FastAPI server so that CORSMiddleware picks up the new list.

If you're hosting the frontend somewhere else (e.g. https://my-ui.example.com) you must add that domain instead.

B. You're logged in but with the wrong role

The backend only lets COMPANY_ADMIN and SUPER_ADMIN update the company profile. If you're logged in as some other role (like FINANCE_USER), the API will return 403 with {"detail":"Only company admins can update company profile"}. 
GitHub

In that case you'd actually see that exact message in the red error box in the UI (because the frontend surfaces error.response.data.detail). 
GitHub

Since you did not see that specific text, this is probably not your case — but it's good to know.

If it is the case: log in as the original company owner / admin, or promote the user to COMPANY_ADMIN in the DB.

C. Your token is missing / expired

If the Authorization: Bearer <token> header is missing or invalid, FastAPI will reject the request with 401 before touching the update logic. The axios interceptor then clears localStorage and navigates you to /login. 
GitHub

If you did not get kicked back to login, this is probably not it.

6. TL;DR what you should do right now

Fix CORS:

Add your frontend origin (very likely http://localhost:5173) to ALLOWED_ORIGINS in the backend config.
